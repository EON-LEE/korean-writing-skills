# 결과 검토

최종 결과를 원문·요청과 대조한다. 실제 확인한 범위만 표시한다. 확인할 수 없는 항목은 해당 없음과 구분한다.

## 중대한 실패: 반드시 수정 또는 확인

- 원문·출처에 없는 사실, 담당자, 기한, 수치, 계산식, 출처를 추가했다.
- 수치, 단위, 날짜, 기간, 범위, 제품명·식별자를 변경했다.
- 조건, 부정, 예외, 경고, 책임, 완료 기준을 누락·변경했다.
- 순차 행동을 동시 행동으로 바꾸거나 실행 순서를 바꿨다.
- 진행·예정·가설을 완료·확정 사실로 바꿨다.
- 권고·허용을 필수로, 관련성을 인과로 바꿨다.
- 인용을 변경하거나 출처의 주장보다 확신을 높였다.
- 미확인 표준 준수, 실행, 제작, 검증을 완료했다고 표시했다.
- 외부 전송·API·비용·자격 증명 처리를 무단 실행했다.

## 작성 규칙

| 항목 | 확인 질문 |
|---|---|
| R01 | 절차의 주체와 행동이 명확한가? 미확인 주체를 만들지 않았는가? |
| R02 | 독립 지시가 분리됐는가? 동시 행동 예외가 정확한가? |
| R03–R04 | 개념·행동의 용어가 일관되는가? 다른 의미를 합치지 않았는가? |
| R05 | 긴 명사 연결의 관계를 이해할 수 있는가? 공식 명칭은 보존됐는가? |
| R06 | 상태·진행·완료·예정과 기준 시점이 정확한가? |
| R07 | 조건의 논리와 부정을 유지하면서 행동 전에 제시했는가? |
| R08 | 목록·표가 정보의 순서·관계를 정확히 보존하는가? |
| R09 | 전문용어·약어가 정확하고 독자에게 필요한 설명이 있는가? |
| R10 | 긴 문장을 검토했는가? 영어 단어 수와 한국어 어절을 혼동하지 않았는가? |
| R11 | 한 문단이 한 주제인가? 6문장 초과 시 분리나 예외를 검토했는가? |
| R12 | 조사·지시어·문장부호가 관계를 모호하게 만들지 않는가? |

| R14–R15 | 사실·추정·권고·의무·범위가 구분되고 근거가 보존됐는가? |

## 설명 형식

- 글·표·도식·HTML·영상의 적합성을 검토하고 요청에 맞는 형식을 선택했는가?
- 도표의 관계, 화살표, 분기와 본문이 일치하는가?
- 차트의 단위·축·기간·출처와 누락값 처리가 정확한가?
- HTML을 만든 경우 입력·계산·출력의 근거와 실패 처리가 명확한가?
- 영상을 만든 경우 장면·내레이션·도식·자막이 일치하는가?
- 미제작 산출물을 검증했다고 쓰지 않았는가?
- 결론·근거·가정·한계·확인 사항을 독자가 찾을 수 있는가?

## 적용 강도와 예외

간결함보다 의미 보존을 우선했는지 확인한다. 필수 양식, 정확한 명칭, 인용, 안전·법적 조건 때문에 생긴 예외를 허용한다. 예외를 이유로 다른 기본 규칙까지 생략하지 않는다.

전체 지침 준용 감사가 요청되면 `source-mapping.md`의 ID별로 다음 상태를 제시한다.

- **적용:** 해당 항목을 실제 반영·검토했다.
- **해당 없음:** 문서 목적·내용상 대상이 없다. 예: 정적 보고서에서 음성 합성 실행.
- **미충족:** 적용 대상이지만 반영하지 못했다. 이유와 필요한 수정 제시.
- **확인 필요:** 입력·출처·도구가 부족해 판단할 수 없다.

문장 길이, 준수율, 이해도 개선을 측정하지 않았다면 숫자로 보고하지 않는다. “모든 지침 적용” 대신 실제 적용 범위와 예외를 보고한다.
