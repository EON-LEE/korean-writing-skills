# korean-clear-writing 평가

스킬을 수정한 뒤 수정 전 버전과 같은 사례로 비교한다. 목표한 문제가 개선됐는지, 기존 동작이 나빠지지 않았는지 확인한다.

## 비교 방법

1. 수정 전 스킬(기준 버전)과 수정한 스킬(후보 버전)을 중립적인 이름의 폴더에 복사한다.
2. 실행 에이전트는 배정된 폴더의 `SKILL.md`와 그 파일이 지시한 참고 자료만 읽는다. 설치된 스킬을 호출하지 않는다.
3. 실행 에이전트는 `cases/`의 요청을 하나씩 처리하고, 사용자에게 줄 최종 응답만 `<출력 폴더>/<버전>/<회차>/<사례>.md`에 저장한다.
4. 버전마다 2회 실행한다.
5. `score.py packet`으로 버전과 회차를 숨긴 채점 자료를 만든다. 응답 순서는 사례마다 무작위로 섞는다.
6. 채점 에이전트는 판정 항목 문장만 기준으로 응답마다 통과·실패와 이유를 JSON으로 기록한다.
7. `score.py score`가 자동 검사 결과와 채점 결과를 합쳐 판정한다.

## 사례

| 사례 | 확인 내용 |
|---|---|
| E1 | 공개 README 검토: 문제 위치, 필수·선택 구분, 경고 위치, 문체 혼용, 공개 범위 |
| E2 | 공개 README 수정: 명령 보존, 경고 선행, 셸별 구분, 문체 통일, 실행 주장 금지 |
| E3 | 전 직원 공지 문체: 문체 통일, UI 문구와 날짜·시간 보존 |
| E4 | 외부 장애 공지: 내부 정보 표시, 사실과 진행 상태 보존 |
| T02, T08, T09, T14, T15, T21 | `assets/acceptance-cases.md`의 기존 사례로 회귀 확인 |

판정 항목은 `criteria.json`에 있다.

- `improvement`: 이번 수정의 개선 대상이다.
- `regression`: 기존 동작을 유지해야 하는 항목이다.
- `critical`: 하나라도 실패하면 중대 실패다.
- `auto`: `score.py`가 문자열 포함이나 새 숫자 추가 여부로 판정한다.

## 사전 판정 기준

실행 전에 정한 기준이다. 결과를 본 뒤 기준을 바꾸지 않는다.

1. 후보 버전의 중대 실패가 0건이다.
2. 회귀 항목에서 후보 버전의 통과 수가 기준 버전 이상이다.
3. 개선 항목에서 후보 버전의 통과율이 80% 이상이고, 통과 수가 기준 버전보다 많다.
4. 채점 누락이 없다.

기준을 하나라도 충족하지 못하면 스킬을 다시 수정하고 후보 버전만 다시 실행한다. 반복 횟수와 이전 결과를 결과 기록에 함께 남긴다.

## 실행 명령

```bash
python evals/score.py packet --outputs OUT --out packet.md --map map.json --seed 20261103
python evals/score.py score --outputs OUT --grades grades.json --map map.json --baseline BASE --candidate CAND --json result.json
```

`OUT`, `BASE`, `CAND`는 실행 환경에 맞게 바꾼다. 실행 결과는 `results/`에 요약한다.

## 한계

- 사례 10개와 버전별 2회 실행은 작은 표본이다. 결과는 회귀 확인용이며 통계적 유의성을 주장하지 않는다.
- 실행과 채점을 언어 모델이 맡으므로 판정 편향이 있을 수 있다. 같은 입력에서도 실행마다 결과가 다를 수 있다.
- 개선 대상 사례와 스킬 수정안을 같은 작성자가 만들었다. 다른 문서에서도 같은 효과가 있다고 보장하지 않는다.
- 자동 검사는 문자열 포함과 새 숫자 추가만 확인한다.
